# 10 — UI

Tauri 2 desktop app with a tray icon. The same process also performs the user-agent duties described in `02-architecture.md`. The UI is a client of the service; it holds no state of its own beyond view preferences.

## Design direction

An instrument, not a billboard. Think profiler or oscilloscope rather than "game booster".

- Dark by default, with a light theme
- Dense, calm, numeric. Tabular monospace numerals for all metrics.
- One accent color. Semantic colors only for verdicts and severity, always paired with a text label or icon.
- No fake gauges, no "health score", no "BOOST" button, no animated particles
- Every number has a unit. Every claim links to its evidence.
- Language is plain and specific: "Chrome used 14% CPU during your match" rather than "background apps detected"

Load the `frontend-design` guidance if available before building screens.

## Navigation

Left rail: **Home · Doctor · Sessions · Lab · Profiles · Changes · Settings**

## Screens

### Home

- Current state strip: Session Mode on/off, active session (game, elapsed, live FPS and 1% low), power source, GPU in use
- "Top findings" (max 3) from Doctor, each with its one-click remedy or guide
- Last session card: headline metrics, hitch rate, top Frame Story cause
- Trend for the most-played game: 1% low and hitch rate over the last 20 sessions, with markers where changes were applied

### Doctor

- "Run check" button (static rules); session rules shown for a chosen session or "recent sessions"
- Findings list sorted by severity then confidence. Each row: title, severity, confidence, key evidence number.
- Detail panel: evidence table, explanation, remedy with what/why/downside/undo, and Apply (or the guide steps)
- "Verified fixed" findings in a separate collapsed group with before/after numbers

### Sessions

- List: game, date, duration, average FPS, 1% low, hitch rate, bottleneck class, badges (lab run, profile changed)
- Compare: select two sessions for a side-by-side summary. Label it "not an experiment" and link to the Lab.

#### Session detail: the timeline

The main view of the product.

- Top: frame-time graph (uPlot), zoom and pan, hitch groups marked
- Beneath, sharing the time axis: event lanes, one per kind: DPC/ISR by driver, hard faults, disk I/O, CPU bursts by process, throttle state, power source, scans/updates/tasks, foreground, Verity's own actions
- Counter tracks, toggleable: CPU total, per-core heat strip, GPU utilization, VRAM, memory available
- Selecting a hitch group opens a side panel listing the events that cover it, sorted by magnitude, with the cause label
- Right column: Frame Story summary: ranked causes with `k/N`, lift, share of excess time, and remedy; unexplained breakdown; caveats
- Must stay responsive on a 3-hour session: downsample by min/max per pixel column and load chunks on demand

### Lab

- Experiment list with verdict chips
- New experiment wizard: game → what to test (action or manual change) → protocol → mode → shows estimated time and, if calibrated, expected blocks
- Runner view: large current instruction ("Run 5 of 12 · arm hidden · start your route now"), progress, validity of completed runs. The arm (A or B) is hidden from the user during manual protocols to avoid bias.
- Result card as specified in `08-lab.md`, with "Keep for this game" when the verdict is Improves

### Profiles

- Default profile and per-game overrides
- Each action row: toggle, risk label, "proven by experiment" badge, a "Test in Lab" link
- Exclusion list editor
- Strict passive mode toggle and the reason if it was set automatically

### Changes (the journal)

- Everything Verity has changed, newest first: action, scope, state, when, session
- Revert per row, "Revert this session", and "Undo everything"
- Crash-recovery reports appear here
- `superseded` entries explain that the user's later change was left alone

### Settings

- Session Mode master switch and the list of default-on actions (the one-time consent screen is reachable here)
- Capture mode default, retention, notification preferences, panic hotkey
- Experimental features switch with a warning
- Capabilities report: what this machine supports and what is unavailable and why (e.g. "Scheduled task visibility: log disabled")
- About: version, licenses including PresentMon, data folder link, "Verity makes no network connections"

## Tray

- Icon states: idle, session active, attention needed
- Menu: Session Mode on/off, current session summary, Panic revert, Open, Quit agent
- Closing the window keeps the agent running in the tray
- Starts with Windows, minimized to tray

## Optional: live monitor window

A small always-on-top window showing live FPS, 1% low and a frame-time sparkline for use on a second monitor or with borderless games. It is a normal top-level window. It is not an in-game overlay and must not be made into one.

## First run

1. One screen explaining the loop: measure, find, fix temporarily, prove
2. System scan (library scan + static Doctor) with real results
3. Consent screen for Session Mode listing exactly which actions are on by default, each with its undo
4. "Play something" prompt: the first recorded session is the real onboarding

## Front-end structure

```
apps/verity-ui/src/
  api/         # typed client generated from verity-ipc types
  state/       # query cache keyed by IPC method; subscriptions feed live views
  screens/     # one folder per screen
  components/  # Timeline, Lanes, Finding, Verdict, ResultCard, JournalRow, ...
  theme/
```

Generate TypeScript types from the Rust IPC types (for example with `ts-rs`) so the two cannot drift.

## Accessibility and quality bar

- Full keyboard navigation; visible focus
- Color is never the only signal
- Text contrast meets WCAG AA
- All screens usable at 1366×768 (common laptop panel)
- No layout shift when live numbers update
